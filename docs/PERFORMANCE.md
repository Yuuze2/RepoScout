# RepoScout 本地性能补充

记录日期：2026-11-26。

将每条旧证据的 Python 解码和独立数据库连接检查，改为单次 SQL 按任务、仓库、commit 与完整文档存在性筛选，再仅迁移尚未索引的旧片段。没有增加会漏掉新证据的永久“迁移完成”标记。

## 测量范围

测量完整 RepositoryIndex.search 调用，包括检索、证据查存、统计及事件写入。每档文件均有等量旧文件证据；每文件 40 行；查询覆盖代码标识符片段、中文短语与零命中。只测已有完整索引的稳态检索，不覆盖首次迁移旧片段。300 文件属于扩容场景，并非默认 60 次 GitHub 请求预算下的典型单任务规模。

每轮每版本 40 次，预热 5 组；两轮每版本合计 80 次。每组随机打乱前后执行顺序，固定种子 26；两轮同一台机器、相同解释器与依赖、相同生成语料，先预热，合并原始样本后取中位数与 nearest-rank P95，不挑较好一轮。

环境：macOS-26.5-arm64-arm-64bit；Python 3.12.14；SQLite 3.53.1。

## 复现

```bash
PYTHONPATH=src .venv/bin/python examples/benchmark_retrieval.py --out examples/performance/retrieval-new.json
```

输出路径必须未存在。脚本生成临时独立数据库，退出时清理；不读取用户任务数据，不调用模型或外网，也不改现有数据库。冻结的基线在 `examples/performance/baseline/`；原始单次时延与代码 SHA-256 在两轮 JSON 中。当前候选代码的哈希在原始结果中记录。

## 验证与限制

新增两项回归覆盖：已有完整索引时连接数不随证据条数线性增长；晚到旧片段、其他任务/仓库/commit 的隔离，以及完整文档替换旧片段。既有检索与旧报告测试继续执行。

全部档位的输出一致性断言通过。本地合成负载数据不能解释为端到端 Agent 调研或故障复现提速，也不证明模型正确率提升。操作系统文件缓存已预热，未测冷启动、网络、LLM、Docker、磁盘紧张、并发争用。新增索引的初次构建和额外存储/写入成本不在 HTTP 计时内；性能数字会随机器、历史规模与负载变化。低负载收益小或不显著的结果同样保留。
